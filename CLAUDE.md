# CLAUDE.md — dotMD (formerly Toc)

Guidance for working on this repo. Read this first each session.

## What dotMD is

**Name:** the app is called **dotMD** (shown in the title bar, window title, tray, `productName`). It was renamed from "Toc" on 2026-10-29, internals included: identifier `com.dotmd.app`, Cargo package `dotmd` (`dotmd.exe`, lib `dotmd_lib`), `dotmd-*` localStorage keys. `src-tauri/src/migrate.rs` copies the old `%APPDATA%` and `%LOCALAPPDATA%` `com.toc.app` folders to `com.dotmd.app` once at startup (old folders stay as a backup); `main.tsx` carries `toc-*` localStorage keys over, and `LEGACY_THEME_VERSION` keeps old `theme.css` files from being regenerated. Below, "Toc" in older text means the same app.

A fast, local **Markdown scratchpad** desktop app. Summon it from anywhere, jot,
get out of the way. Everything is stored locally as plain `.md` files.

- **Stack:** Tauri 2 (Rust backend) + React 19 + TypeScript + Vite + Tailwind v4 + CodeMirror 6 + Zustand.
- **Design principle:** Rust owns files, data, and OS integration; React owns everything you see. The frontend never touches disk directly — it calls typed wrappers in `src/api.ts` that `invoke` Rust commands.
- **Product model:** `scratch` (shown in the UI as **"Untitled"**; the file stays `system/scratch.md`) is the inbox, everything else is the archive. `scratch` lives in a separate `system/` folder — **hidden from the Files list, search, and tags**. The global summon shortcut shows the window **as you left it** (Rust emits a `summon` event; the frontend just focuses the editor if a note is open). Untitled is opened with `Ctrl+Shift+N` (`openInbox` action; `Ctrl+N` creates a new note). **No note open is a real state:** closing the last tab sets `currentNote` to `""` (`closeEditor()` in store.ts, persisted as `last_note: ""` so a relaunch starts empty); `Editor.tsx` then adds `.empty`, hides the tab bar + page (CodeMirror stays mounted) and renders `EmptyEditor` (faint `assets/logo-mark.svg` watermark via CSS mask + clickable shortcut rows from `ACTIONS`). `save`/`setContent`/`fileAndClear`/`setDocMode`/`syncExternalNotes`/`focusEditor` all no-op on `""`; always guard new `currentNote` uses the same way. `Ctrl+Enter` files the buffer into its own note and clears scratch; `Ctrl+P` / search get you back.

## Running the app — environment note (toolchain repaired)

Plain commands now work from any **new** terminal:

```powershell
npm run tauri dev       # hot-reload dev
cargo test              # from src-tauri/
```

**Background:** this machine's VS C++ Build Tools install was incomplete
(`vswhere.exe` missing, Windows SDK lib paths unregistered), so a plain build
used to fail to link with `LNK1181: cannot open input file 'dbghelp.lib'`. The
MSVC compiler/linker and the Windows SDK files ARE on disk; the fix was just to
point the linker at them. This was repaired by **persisting `LIB` / `INCLUDE`
and PATH additions to the user environment** (MSVC `14.44.35207` bin + Windows
SDK `10.0.26100.0` bin + `%USERPROFILE%\.cargo\bin`).

- Open a **new** terminal after any session where these were changed (existing shells keep stale env).
- `scripts/dev.ps1` still works as a fallback and **auto-detects the newest** MSVC + SDK, so if those ever update to new version folders and the pinned user-env paths go stale, use `dev.ps1` (or re-run the persist step with fresh versions).
- Full official alternative (needs admin/UAC): `winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"`.

### Dev loop facts
- `npm run tauri dev` gives hot reload: **frontend edits HMR instantly**; **Rust edits auto-recompile** (~5–20s) and relaunch the window.
- Editing a Rust file while the app runs can transiently fail the auto-rebuild if the struct is mid-change or `dotmd.exe` is still locked — just relaunch.
- Before relaunching, kill stragglers: `Get-Process dotmd,cargo | Stop-Process -Force` and free port 1420.
- Typecheck frontend: `npx tsc --noEmit`. Rust tests: `cargo test` (inside the MSVC env).

## Data files (`%APPDATA%\com.dotmd.app\`)

**Dev builds use `dev-data/` in the repo, not `%APPDATA%`.** `storage::data_root` picks the folder: `DOTMD_DATA_DIR` env var if set, else `<repo>/dev-data/` in debug builds (`cfg!(debug_assertions)`, i.e. `npm run tauri dev`), else `%APPDATA%\com.dotmd.app\`. Everything (config, todo, watcher, images, projects, backup) goes through `storage::data_dir`, so never call `app_data_dir()` directly. `lib.rs` setup adds that folder's `assets/` to the asset-protocol scope at runtime (tauri.conf.json only allows `$APPDATA/assets`). `dev-data/` and `private/` (personal files) are git-ignored. To run dev on the real notes: `$env:DOTMD_DATA_DIR = "$env:APPDATA\com.dotmd.app"; npm run tauri dev`.

```
system/
  scratch.md            # home note summon lands on (protected; NOT in the notes list/search/tags)
notes/
  <your notes>.md       # notes not in any project
  <Project slug>/       # a project's linked notes (projects::sync_folders); one level only
    <note>.md
assets/                 # images linked from notes as ../assets/<file> (works from notes/ and system/)
projects/
  <slug>.md             # one per project: front matter (name, logo, created, goal, description, notes: ["[[note]]"]) + a free body the app never touches
trash/                  # everything deleted, laid out like the app (trash.rs); <stamp> = "YYYY-MM-DD HH.MM.SS"
  notes/<stamp>__<name>.md
  images/<stamp>__<file>
  projects/<stamp>__<slug>/
    project.md          # the project page
    tasks.md            # its tasks (todo.md lines) + <!-- colour: … -->, restored with it
  tasks.md              # single deleted tasks, `## <stamp>` groups (todo.md lines)
todo.md                 # checkbox list, see format below
theme.css               # injected over defaults at startup; Appearance settings write it
settings.json           # autosave, global_shortcut, styled_default, keybindings, etc.
```

### todo.md line format (keep human-readable)
```
- [ ] [Subject] name <!--createdISO|deadlineYYYY-MM-DD|description-->
```
- Subject is inline in brackets; metadata hides in an HTML comment.
- `split_meta` uses `splitn(3,'|')` so description is the remainder (may contain `|`).
- Description encodes newlines as `\n` and `-->` as `--&gt;` (`encode`/`decode` in `todo.rs`). Round-trip is covered by tests.

## Rust commands (frontend ↔ backend)

In `src-tauri/src/`, registered in `lib.rs`:
- `trash.rs`: the **one `trash/` folder** (tree above). `notes_dir` / `images_dir` / `projects_dir` / `tasks_file`, `free_stem(dir, base, ext)` (`<stamp>__<base>`, `-2` on a clash), `deleted_at(id)` (stamp → secs; Storage sorts trash by delete time). Tasks: `trash_tasks(tasks)` → group stamp (called by `store.deleteTodosAt` and `deleteSubject` for plain subjects), `untrash_tasks(stamp)` (Undo), `restore_tasks(ids)` → the Todos (frontend appends via `store.restoreTrashedTasks`); task ids are `<stamp>#<n>`. Projects: `delete_project(name, tasks, colour)` writes the folder, `restore_project(stem)` → `{tasks, colour}` (Undo ignores them, it re-inserts at the old positions; Storage → Trash appends them). `migrate_layout(data)` (startup + after import) moves old `notes/.trash`, `assets/.trash`, `projects/.trash` here, restamping `<unix-secs>__` names. `storage::trash_dir` = trash/notes. Backup's `DIRS` includes `trash` (only with Include trash). Tests cover restamping, task groups, migration.
- `storage.rs`: `list_notes` (`NoteMeta` = name, title (first line), `preview` (next non-empty line, for list rows), modified), `read_note`, `note_modified` (file mtime, incl. scratch — feeds the page header date), `save_note`, `create_note`, `delete_note`, `rename_note`, `search_notes`, `file_text` (file-&-clear), `scan_tags`, `list_trash`, `restore_note`, `duplicate_note`, `reveal_note`. `delete_note` **returns the trash stem** (for precise undo); `duplicate_note` writes a uniquified "<name> copy"; `reveal_note` opens the OS file manager selecting the `.md` (`explorer /select,` on Windows). Atomic writes (temp + rename); all names pass `clean_name` (no `..`, separators, bad chars); `scratch` is protected. **Delete is non-destructive**: `delete_note` moves the file to `trash/notes/` as `<stamp>__<name>.md`; `restore_note(stem)` moves it back (uniquifying; trash ids pass `clean_trash_id`, which allows the stamp on top of a full 120-char name); old `.trash/` folders are skipped by the list/search/scan filters. `scan_tags` extracts inline `#tag` tokens (word-boundary, letter-initial — headings excluded) → tag→notes, busiest first. The protected `scratch` note lives in **`system/`** (routed there by `note_path`; `ensure_scratch` seeds it and migrates a legacy copy out of `notes/` on startup; rejected by delete/rename), so it never appears in list/search/tags. The Daily page feature was removed: `retire_daily` (startup) turns an old `system/daily.md` with text into the ordinary note `Daily` (or `Daily 2`…), and trashes a blank/seeded one; `init` in store.ts maps an old `daily` tab/last_note onto that note case-insensitively.
- `images.rs`: `assets_path`, `save_image` (raw invoke body + `ext` header — used by paste), `import_image(path)` (copy a picked file; stem sanitized to `[A-Za-z0-9_-]`), `unused_images` / `clean_unused_images` (scans notes/, trash/notes/ **and** system/ text for `assets/<file>`; orphans move to `trash/images/`). All return/accept `../assets/<file>` links. Served to the webview via Tauri's **asset protocol** (`tauri.conf.json` `assetProtocol` scoped to `$APPDATA/assets/**`, Cargo feature `protocol-asset`); file picker is `tauri-plugin-dialog` (`dialog:allow-open`).
- `links.rs`: `[[note]]` / `[[note|label]]` links. `rewrite_links` runs inside `rename_note` (rewrites every link in notes/, system/ and trash); `backlinks(name)` → `SearchHit`s of live notes linking in (Outline rail's "Linked from").
- `vault.rs` (Storage view backend): `storage_report` (every note's bytes/words/linked-image count, every asset's bytes + which live notes link it + how many trashed notes do, and both trashes), `trash_images(files)` → trash/images as `<stamp>__<file>` (returns trash names for undo), `restore_image(id)` (back under the original name — links depend on it; errors if taken), `delete_forever(items)` / `empty_trash()` (the **only hard deletes**, confined to `trash/` (notes, images, project folders, task lines in trash/tasks.md); return bytes freed), `remove_tag(tag)` (strips the same `#tag` tokens `extract_tags` finds, any case, plus one neighbouring space; returns each changed note's old text for undo). Tests cover tag stripping, trash-name round-trip, path rejection.
- **Project folders** (`projects.rs` `sync_folders`, run at startup, after every project mutation, and from `store.syncExternalNotes` via `sync_project_folders`): a linked note lives in `notes/<project file stem>/` (the slug, made unique like the file — "web 2" beside "Web" — so projects never share a folder; first project by name wins; linked notes left in a folder no linking project owns move home too; `rename_project` moves the folder first and falls back to moving the notes one by one if Windows won't rename it); a `.md` dropped into a project folder (e.g. by Claude Code) is auto-linked. Note names stay unique across folders, so everything still addresses notes by name: always go through `storage::note_path` / `find_note` / `note_files` / `taken`, never `notes_dir().join(name)`. `update_project` moves unlinked notes out *before* writing (else the sync re-links them); `rename_project` renames the folder; `delete_project` empties it back to notes/. `project_folder` / `open_project_folder` back the project ⋯ menu's **Open terminal here** / **Show folder**.
- `projects.rs`: **Projects** = a to-do subject promoted with a page. `list_projects`, `create_project` (returns the existing one if the name is taken), `update_project` (rewrites front matter, keeps the body), `rename_project(from, to)` (moves the file to the new slug; renaming onto an existing project **merges**: target keeps its fields, fills blanks + gains notes, source → trash), `delete_project(name, tasks, colour)` (→ `trash/projects/<stamp>__<slug>/` with project.md + tasks.md, returns the folder name; the frontend passes the tasks it removed — `store.deleteProject` removes the tasks), `restore_project(stem)`. Hand-rolled front-matter reader/writer (no YAML crate): scalars quoted with JSON escaping only when needed, `notes:` is a list of `"[[name]]"` so `links::rewrite_links` (which also scans `project_files`) keeps membership through note renames. File names are `slug(name)` (reserved chars → `-`); lookups always go by the front-matter `name`. `images::all_note_text` + `vault::storage_report` count project logos as used (`ImageInfo.used_by_projects`), so Clean unused never trashes a logo. Watcher emits `projects-changed`. Tests cover round-trip, hand-written files, slugs.
- `backup.rs`: `export_backup(path, include_trash)` zips notes/, system/, projects/, assets/, todo.md, settings.json, theme.css (mirroring the data-dir layout, so unzipping into `%APPDATA%\com.dotmd.app\` restores it) plus a `dotmd-backup.json` manifest; skips `.trash/` unless asked, `*.tmp`, window state; keeps file mtimes; writes `<file>.zip.tmp` then renames; runs in `spawn_blocking`. Returns `BackupSummary` (path, files, bytes). `reveal_file(path)` shows it in the file manager (shares `storage::reveal_path` with `reveal_note`). Frontend: Settings → **Backup** (`BackupSection`: save dialog via `dialog:allow-save`, Include trash switch, saves the open note first, result row with Show in folder). **Import**: `inspect_backup(path)` (needs the manifest with `app: "dotMD"`; returns `BackupInfo` counts for the confirm step) and `import_backup(path, mode)`. Both modes first zip the current data (incl. trash) to `backups/before-import-<stamp>.zip` (not in `DIRS`, so never re-exported). Entries pass `allowed()` (plain components under DIRS, or one of FILES; blocks zip-slip; skips `*.tmp`); mtimes restored. **merge** never overwrites: new files added, identical skipped, differing `notes/*.md` → `<name> (imported).md` (matched by note name, so a note now in a project folder counts as present), differing scratch → `notes/Untitled (imported).md` (an old backup's `system/daily.md` → `Daily (imported).md`), differing projects/assets/trash/theme → yours kept, `todo.md` appends tasks not already present (key text+subject+created, via `todo::parse/render`), `settings.json` only gains missing `subject_colors` + `view_only_notes`. **replace** unpacks to `.import-staging/` first, then empties each data folder in place (folders kept so the watcher survives) and moves the staged files in. UI (`ImportRows`): pick → summary → Merge / Replace (two-click armed) / Cancel; merge refreshes the store in place, replace does `location.reload()`. Tests cover path filtering, merge, replace.
- `terminal.rs` (Terminal view backend): `term_spawn(cols, rows, cwd?)` opens a PTY (`portable-pty`, ConPTY on Windows) running `cmd.exe` (`$SHELL` elsewhere) in `cwd` or the home folder → `Spawned {id, cwd, shell}`; a reader thread emits `term-data {id, data}` (UTF-8 split-safe via `utf8_ready`), a waiter thread emits `term-exit {id, code}` then drops the session (with ConPTY that's what ends the output pipe). `term_write(id, data)`, `term_resize(id, cols, rows)`, `term_kill(id)`. State = managed `Terminals` (id → master/writer/killer).
- `todo.rs`: `load_todos`, `save_todos` (Todo = text, done, created, deadline, subject, description).
- `config.rs`: `load_settings`, `save_settings`, `load_theme`, `save_theme`.
- `shell.rs`: tray icon (Open/Quit, click-to-toggle), `show/hide/toggle_window` (`toggle_window` returns whether it showed the window, so the summon shortcut can land on scratch).
- `watcher.rs`: filesystem watcher (`notify` crate) over `notes/` (recursive) + the data dir (for `todo.md`); emits `notes-changed` / `todo-changed` on external file changes, and `trash-changed` for anything under `trash/` (App.tsx → `refreshTrash` + bumps `store.trashSeq`, which the Storage view reloads on). Config writes (`settings.json`, `theme.css`) and `*.md.tmp` atomic-write temps are filtered out so routine saves don't self-trigger.
- `lib.rs`: plugins (single-instance — **release builds only**, a second launch shows the running window; window-state, global-shortcut); starts the filesystem watcher at startup; global summon shortcut (registered from `settings.global_shortcut` at startup — **changing it needs a restart**) emits a `summon` event when it shows the window; close-to-tray + hide-on-blur window events.

## Conventions / gotchas

- Global key handler is **capture-phase** so shortcuts beat CodeMirror; it stands down while `store.recording` is set (keybind capture in Settings). `Escape` is left to overlays / the autocomplete menu (not a binding).
- **View-scoped keyboard**: `Calendar` (arrows / `PgUp`/`PgDn` / `N` / `Enter` / `Y` / `T`; also stands down while the edit sheet is open) and `FilesView` (`F2` / `Delete`) attach their own **window-level** `keydown` listeners, mounted only while that view is shown. They bail out when focus is in an `INPUT`/`TEXTAREA` or a context menu is open, and `Calendar` also bails on `ctrl`/`meta`/`alt` so modified combos (e.g. `Ctrl+T`) fall through to the global handler. The keys they use (`N`, arrows, `F2`, `Delete`, `Enter`) are intentionally **not** in `ACTIONS`, so the capture-phase global handler ignores them. Calendar steals focus on mount so arrows don't leak into the editor beneath it. **TodoPanel** focuses its root on mount (arrows work immediately) and exposes `focusTodoPanel`. The **toolbar-nav** handler (`App.tsx`, Ctrl+T) is capture-phase and `stopPropagation`s `↑/↓` while in nav mode so Calendar's arrow listener can't double-fire. Editor `Tab`/`Shift+Tab` = indent/outdent (`indentWithTab` + `indentUnit`, 3 spaces); `Ctrl+J` switches editor↔tasks via the `focusEditor`/`focusTodoPanel` handles.
- `reveal_note` only `spawn()`s the file manager (doesn't wait); Windows `explorer /select,` returns a non-zero exit even on success, which is why we don't check the status.
- CodeMirror replace decorations from a **ViewPlugin cannot span line breaks** — that's why concealed fence lines leave a blank line (would need a StateField to collapse).
- `focusEditor()` (from `components/Editor.tsx`) and `focusTodoPanel()` (from `components/TodoPanel.tsx`) are module-level focus handles, used by the `Ctrl+J` action in `actions.ts`.
- Not yet persisted across sessions: the styled-view toggle respects `settings.styled_default` at startup but the live toggle is session-only; sidebar width is in localStorage; selected theme name is in localStorage (css itself persists to `theme.css`).

## Working preferences

- Keep `todo.md`/notes human-readable plain Markdown.
